# 检索与重排优化

RAG 系统的核心在于“检索”。如果检索到的文档片段与问题不相关，大模型再强也无法生成准确的回答。本指南介绍如何优化检索效果。

## 基础参数调优

### 调整 Top-K

`TOP_K` 决定每次检索返回多少个文档片段。

```env
TOP_K=3
```

- **值太小**：可能漏掉关键信息。
- **值太大**：引入无关噪音，增加大模型处理负担。

**建议**：一般场景设置为 `3~5`。如果文档内容分散，可调大至 `8~10`。

### 调整相似度阈值

`SCORE_THRESHOLD` 用于过滤低质量检索结果。低于此阈值的片段将被丢弃。

```env
SCORE_THRESHOLD=0.7
```

**建议**：如果你的文档语义差异大，可降低至 `0.5`；如果追求精准，可提高至 `0.8`。

## 开启重排（Rerank）

向量检索是“粗排”，速度快但精度有限。重排模型（Cross-Encoder）会对 Top-K 结果进行“精排”，显著提升相关性。

### 配置重排模型
在 `.env` 中开启：

```env
ENABLE_RERANK=true
RERANK_MODEL=BAAI/bge-reranker-base
```

### 重排原理
- **向量检索（双塔模型）**：问题与文档分别编码，速度快，但交互不足。
- **重排（交叉编码器）**：将问题与文档拼接后一起输入模型，计算相关性得分，精度高。

:::tip 推荐
在文档量大（> 1000 篇）或对准确性要求极高的场景下，强烈建议开启重排。
:::

## 混合检索（Hybrid Search）

纯向量检索对**专有名词、错误码、型号**等精确匹配能力较弱。混合检索结合了关键词检索（BM25）和向量检索的优势。

在 `.env` 中开启：

```env
ENABLE_HYBRID_SEARCH=true
HYBRID_ALPHA=0.5  # 0 表示纯关键词，1 表示纯向量
```

## 检索效果评估

如何判断检索变好了？建议收集 20-50 个典型问题，人工标注正确答案，然后计算：
- **召回率（Recall）**：正确片段被检索到的比例。
- **精确率（Precision）**：检索结果中正确片段的比例。

详见 [效果评估](../05-原理与最佳实践/evaluation.md)。

## 常见问题

| 问题 | 原因 | 解决方案 |
| :--- | :--- | :--- |
| 回答“我不知道” | 检索结果为空 | 降低 `SCORE_THRESHOLD`，增加 `TOP_K` |
| 回答偏离主题 | 检索引入了噪音 | 开启 Rerank，提高阈值 |
| 专有名词找不到 | 向量模型对名词不敏感 | 开启混合检索 |
