# 分块策略

分块（Chunking）是 RAG 系统中**最容易被忽视，却对最终效果影响最大**的环节之一。本页介绍常见的分块策略及最佳实践。

## 为什么分块如此重要？

- **上下文窗口限制**：大模型无法一次性处理整本 PDF。
- **语义稀释**：一篇 10000 字的文档，如果整篇向量化，其向量会变得非常“模糊”，无法准确匹配具体问题。
- **检索精度**：小块更容易与具体问题精确匹配。

## 常见的分块策略

### 1. 固定长度分块（Fixed-size Chunking）
最简单的策略，按固定字符数或 Token 数切分。

```python
# 示例：按 500 字符切分
chunk_size = 500
chunks = [text[i:i+chunk_size] for i in range(0, len(text), chunk_size)]
```

- **优点**：实现简单，速度极快。
- **缺点**：容易在句子中间切断，导致语义不完整。
- **适用场景**：日志、纯文本等结构松散的内容。

### 2. 重叠分块（Overlapping Chunking）
在固定长度的基础上，让相邻块之间有重叠部分。

```env
CHUNK_SIZE=500
CHUNK_OVERLAP=50
```

- **优点**：缓解语义断层，保留上下文连贯性。
- **缺点**：增加向量数量，略微增加存储和检索成本。
- **推荐**：**大多数场景的默认选择**。重叠大小通常设置为块大小的 10%~20%。

### 3. 递归分块（Recursive Chunking）
按照优先级依次尝试不同的分隔符（如段落 `\n\n`、句子 `\n`、空格），直到块大小满足要求。

- **优点**：尽可能保持段落和句子的完整性。
- **缺点**：实现稍复杂。
- **适用场景**：Markdown、技术文档、论文。**强烈推荐此策略**。

### 4. 语义分块（Semantic Chunking）
使用 Embedding 模型计算相邻句子的语义相似度，在语义发生较大变化的地方切分。

- **优点**：块内语义高度一致，检索精度极高。
- **缺点**：计算成本高，速度慢。
- **适用场景**：对精度要求极高的专业领域问答。

## 分块大小怎么选？

| 文档类型 | 推荐 Chunk Size | 推荐 Overlap |
| :--- | :--- | :--- |
| FAQ / 短问答 | 100 ~ 200 | 10 ~ 20 |
| 技术文档 / 教程 | 500 ~ 800 | 50 ~ 100 |
| 学术论文 / 长文 | 800 ~ 1200 | 100 ~ 200 |
| 代码文档 | 按函数/类切分 | 不适用 |

:::tip 最佳实践
没有万能的分块参数。建议先用 500/50 作为基线，然后根据 [效果评估](evaluation.md) 的结果逐步调整。
:::

## 特殊文档的处理

- **Markdown**：按标题层级（`#`、`##`）切分，保留结构信息。
- **PDF 表格**：单独提取表格，转换为 Markdown 或 CSV 格式后单独向量化。
- **代码**：按函数或类切分，保留完整的逻辑单元。
