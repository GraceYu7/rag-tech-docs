# 错误码

本页列出 API 可能返回的所有错误码及其排查建议。

## 错误响应结构

当 API 调用失败时，会返回对应的 HTTP 状态码和错误信息：

```json
{
  "code": 40100,
  "message": "Invalid API Key",
  "data": null
}
```

## 通用错误码

| HTTP 状态码 | 业务码 | 说明 | 排查建议 |
| :--- | :--- | :--- | :--- |
| 400 | 40000 | 请求参数错误 | 检查请求参数类型和必填项 |
| 401 | 40100 | 未授权，API Key 无效 | 检查 Header 中的 Bearer Token |
| 403 | 40300 | 无权限访问该资源 | 确认 API Key 是否有对应权限 |
| 404 | 40400 | 资源不存在 | 检查请求路径或资源 ID |
| 429 | 42900 | 请求过于频繁，触发限流 | 降低请求频率，参见 [限流与配额](rate-limits.md) |
| 500 | 50000 | 服务器内部错误 | 查看后端日志，排查异常 |

## 业务错误码

| 业务码 | 说明 | 排查建议 |
| :--- | :--- | :--- |
| 40001 | 文件格式不支持 | 确认上传的是 PDF/MD/TXT |
| 40002 | 文件大小超限 | 单文件不超过 10MB |
| 40401 | 文档不存在 | 检查 `document_id` 是否正确 |
| 50001 | 向量库连接失败 | 检查向量数据库服务状态 |
| 50002 | 大模型调用失败 | 检查 API Key 余额及网络连接 |

## 排查步骤

如果遇到错误，建议按以下步骤排查：
1. 检查 HTTP 状态码和业务码，确定错误类型。
2. 对照上表，执行对应的排查建议。
3. 查看后端日志 `rag-demo/logs/app.log` 获取详细堆栈。
4. 如果问题仍未解决，请提交 [GitHub Issue](https://github.com/GraceYu7/rag-tech-docs/issues)。
